# v0.1.2 Release Notes

Maintenance update to make the extraction trust boundary visible in both output
formats. A successful extraction is not semantic verification.

## Changed

- JSON success envelopes add `content_unverified` to the existing `warnings`
  array. Output Schema v0.1, existing JSON keys, provider content and exit codes
  are unchanged. Consumers should tolerate unfamiliar warning codes rather than
  assume the list is empty.
- Markdown adds `content_verification: "unverified"` to front matter and a
  visible notice before the provider body. Consumers that assume fixed front
  matter keys, line positions or byte-for-byte output should update snapshots
  and parse front matter by key.
- Existing saved output is not rewritten. No additional source is fetched to
  verify the result. Check claims, version ranges, scope and freshness against
  the original publisher.

## Version Mapping

- Python package version: `0.1.2`
- Corresponding Git tag: `v0.1.2`

Before distribution and post-publication fresh-install checks succeed, the
repository install commands and plugin fallback stay pinned to the verified
published `0.1.1`. Updating those entry points is a separate follow-up after
verification. The PyPI description bundled with this release targets `0.1.2`.

Extraction still sends only the selected public URL to the experimental
`firecrawl-keyless` provider. Provider availability is not guaranteed; output
remains untrusted.
